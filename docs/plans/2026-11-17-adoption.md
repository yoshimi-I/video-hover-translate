# Adoption and identity plan

Goal: Make the public extension recognizable and useful to people who do not own the original private backend.

Priorities: (1) a small-size legible play/speech brand mark with editable SVG source; (2) direct OpenAI-compatible and local Ollama support while preserving the existing custom API; (3) due-date review scheduling and a non-persistent sample demo.

Approach: Add a pure provider module shared by the service worker and settings. Request permission only for the configured host on an explicit Save click, require HTTPS except loopback, and namespace caches by provider/endpoint/model. Keep keys out of URLs, exports and logs. Schedule correct answers after 1, 3, 7, 14, 30 and 60 days and wrong answers after 10 minutes; this is a simple deterministic schedule, not FSRS. Existing review counters remain readable. Demo answers remain in memory and never change real history or progress.

Verification: failing tests before implementation for configuration, payloads, response validation, network/auth failures, settings permission denial, provider-specific caches, scheduling migrations, due filtering and demo isolation. Run existing playback/export tests, inspect narrow-panel screenshots and icon sizes, update public docs/screenshots and publish a versioned release after review and CI.

Research: asbplayer (https://github.com/asbplayer/asbplayer) emphasizes vocabulary mining/Anki; LST (https://github.com/DarlingGoose/LST) supports direct providers and Ollama. We infer that setup friction, a safe demo and a repeatable review loop are more valuable initial adoption work than adding many streaming sites. Star growth is not guaranteed.
